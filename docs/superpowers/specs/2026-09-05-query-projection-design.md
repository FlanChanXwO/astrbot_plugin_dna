# 查询接口消费者专用最小数据投影

日期：2026-09-05

## 背景

二重螺旋上游接口经常在同一个响应中返回多个消费者的数据。例如签到日历会附带
`roleInfo`，而角色卡片、密函、日常便签和周报又会分别读取同一角色接口的不同部分。
旧实现直接复用全量 legacy response model，导致未参与当前命令的嵌套字段缺失时，整个查询
被误归类为服务异常。典型案例是签到日历本身完整，但附带的残缺 `roleInfo` 使卡片无法渲染。

本次改动只收窄插件本地的解析、领域存储和渲染输入，不改变上游请求参数，也不要求上游
支持字段选择。

## 数据边界规则

查询型数据按以下单向链路流动：

```text
上游 DNAApiResp envelope/status/data 检查
    → 消费者专用 Pydantic projection
    → 领域 DTO / value object
    → 最小 renderer view / template payload
```

1. **Envelope 检查仍然集中保留。** 成功状态、凭据失效、网络异常和 `data is None` 仍按
   现有 transport 错误类别处理；响应状态失败不会伪造成空成功。
2. **Projection 只声明当前消费者读取的字段。** 已用于业务判断、模板展示或资源定位的
   字段保持必需；未使用的 legacy 字段不再因为缺失而阻断查询。所有 projection 使用
   `extra="ignore"`，上游新增字段不影响现有命令。
3. **领域 DTO 不再承担上游完整响应形状。** DTO 只保存 use case 和 renderer 后续真正
   需要的值；默认值仅沿用已有领域合约中的 `None`、空集合或计数语义，不为必需业务字段
   伪造成功。
4. **Renderer 直接构造最小 view。** 新命令路径从领域 DTO 生成模板 payload，不将 DTO
   回拼为 `DNACalendarSignRes`、`DNAItemWeeklyReportRes`、`DNARoleForToolRes` 等完整
   legacy model。旧的 `draw_*` 入口继续保留为兼容适配器。

## 消费者投影

### 玩家角色

- 角色卡片、角色选择和角色详情继续使用完整 `RoleOverview`/详情投影；角色、近战武器和
  远程武器列表仍是完整卡片能力的一部分。
- 新增 `RoleHeader`，只包含 `roleId`、角色名、等级和统计参数。签到日历、日常便签和周报
  使用它，不要求完整角色/武器展柜。

### 签到日历与社区任务

- 签到日历严格校验周期和奖励日历实际使用的字段；顶层签到状态仍可选。
- `roleInfo` 是接口附带信息，不是日历模板的必需输入。缺失、空对象或半截对象均按
  `None` 处理；真正缺失周期或奖励字段仍显式失败。
- 社区任务只校验任务名称、次数和进度等当前服务/模板读取字段，不再强制未使用的
  `skipType`。

### 日常便签与周报

- 日常便签严格校验四组进度条所需的计数；`draftInfo` 和锻造槽位中的产品名、时间等
  可选字段按空槽语义处理。
- 周报严格校验日期、周类型、分类名和资源项身份/名称；分类选项、品质、数量、图标等
  沿用现有可选/默认语义，空分类和未知字段可正常保留。
- 两类命令各自解析角色头部，不共享完整角色响应模型假设。

### 密函、公告与活动日历

- 密函只解析 `instanceInfo`、分节和实例的 `id/name`，分节类型沿用接口位置语义；不再
  调用带额外模型校验器的完整 legacy `DNAMHRes`。
- 公告正文和活动日历继续按各自服务/渲染器消费的映射解析，缺失真正正文或必要活动
  标识时显式报告结构错误。

## 兼容与非目标

- 不修改 `src/utils/api/model.py` 中的全局 legacy response model；旧脚本和旧绘制入口仍可
  使用原约定。
- 不改变请求 URL、请求参数、命令清单、数据库结构、运行期数据目录或依赖清单。
- 登录、签到执行、订阅、刷新等写操作的响应协议不在本次主动重构范围内。
- 上游返回内容本身不会减少；“只拿需要的数据”仅指插件在 transport、领域和 renderer
  边界上的本地投影与保存。

## 验收重点

- 残缺非必要 `roleInfo` 不再使签到日历变成通用服务异常。
- 缺失真正必需的周期、奖励、周报日期/身份或公告正文仍可观测地失败。
- 角色卡片、签到日历、日常便签、本周/上周周报、密函/公告渲染和旧绘制入口保持回归
  可用；图片仍由现有 T2I/HTML 资源链路生成。
