# 运行期用户文案

## 目录边界

插件运行期用户可见提示统一维护在插件根目录的 `i18/zh/tip.json`，通过
`src/infrastructure/i18n/` 的标准库 loader 按点号 key 读取，例如
`account.login_failed`。

这里的 `i18/` 是插件自己的运行期资源目录，不是 AstrBot 的 WebUI 国际化目录。
`.astrbot-plugin/i18n/*.json` 仍保留给 AstrBot 官方约定的插件元数据与配置 schema
国际化；两者不能混用。

## 兼容层

`src/modules/*/messages.py` 和 `src/utils/msgs/notify.py` 继续保留原有常量、模板和
函数名，作为调用方兼容层。兼容层正文从 `i18/zh/tip.json` 读取，业务代码可以逐步
迁移到更直接的 loader 调用，而不需要一次性改写全部调用方。

动态文案只把模板放入目录；列表排序、换行组合、日期格式化、条件判断和权限判断仍
由 Python 代码负责。订阅类型、命令 ID、枚举值和持久化域值不作为文案迁移。

## 加载失败

默认 locale 当前固定为 `zh`。插件构造 runtime 时会显式校验文案目录：文件不存在、JSON
损坏、根节点或叶子类型错误、空文案以及非法模板都会直接报错。读取不存在的 key 或
调用模板时缺少参数也会抛出带 key 的异常，不会静默回退到旧文案。

凭据失效提示由 transport 统一分类：当前用户显示“登录已失效，请重新登录”，查询
目标用户显示“账号凭据无效，请重新登录”；非认证服务异常显示“服务暂不可用，请稍后重试”。
上游响应正文、Token、URL 和内部 detail 不会回显给用户。
