# Dashboard 管理页

## 入口与范围

页面通过已登录的 AstrBot Dashboard 插件入口打开，管理 API 只接受 Dashboard 管理员认证；
不存在独立的未认证入口。直接访问管理 API 未携带认证时返回 `401/403` 属于预期的保护行为；
状态核验必须使用 Dashboard 认证上下文，不能用未认证响应或任意 HTTP `2xx` 推断插件已成功加载。
左下角版本来自 `metadata.yaml`，页面只包含三个功能区：

1. 定时任务、投递目标和离群用户探测；
2. 全局账号、玩家绑定和卡片预览；
3. 角色别名。

页面不提供帮助命令管理、数据图表、账号创建、任务创建、自定义 cron/interval 类型或武器别名
管理。破坏性写操作使用确认弹窗，成功后重新读取服务端状态；页面不把数据或凭据写入浏览器
`localStorage`/`sessionStorage`。

## 全局账号与身份

账号绑定和凭据按 `(user_id, uid)` 管理，个人隐私按裸 `user_id` 管理，群强制隐私按裸
`group_id` 管理。它们对所有 AstrBot 平台和 Bot 共享：同一 `user_id` 字符串在不同平台/Bot
上会读到同一账号、凭据和隐私设置。平台或 Bot 不再是这些持久化表的隔离键；相同字符串代表
不同真实用户的碰撞风险已由部署决策接受。

`EventActor.bot_id` 仍会用于当前事件投递、群探测和 legacy transport 上下文，但只是运行期字段，
不参与上述账号、凭据或隐私查询。绑定来源 `group_id` 用于记录上下文，也不改变账号身份键。

## 账号编辑与玩家预览

- 账号列表只读取 UID、active、来源群和 App 凭据状态，不默认返回 secret。
- 打开已有账号详情后，可查看和编辑 App Cookie、device code、d_num、refresh token 和状态字段；
  `user_id` 与 `uid` 是只读身份键。页面不允许借编辑接口新建账号，Web 凭据字段和 Web 登录
  入口已移除。
- 明文凭据只在已认证管理请求和编辑抽屉的内存生命周期内可见。后端响应设置 `Cache-Control:
  no-store`，但管理员仍须防止截图、录屏、剪贴板、浏览器扩展、代理和宿主日志泄露；关闭抽屉
  后应确认页面不再保留凭据。
- 基本卡和角色详情卡预览使用目标账号的凭据与既有 renderer，完整显示 UID 并绕过普通隐私设置；
  预览不修改隐私表、不暴露本地文件路径。无凭据或上游/T2I 不可用时会显式失败，不伪造图片。

## 任务与投递目标

页面展示四个内置任务的运行状态、调度规则、关联群聊/会话目标和带时区的下一次运行时间。
每日签到和公告轮询可编辑已有规则，密函推送展示配置的 `HH:<minute>`；所有任务均可暂停/恢复，
页面不创建新任务或新任务类型。后端管理 API 只允许对已有投递
目标进行更新/删除，当前页面以展示目标为主，也不提供目标创建。

每日签到和公告轮询的调度修改会同步其 typed 配置（配置存储可写时）；密函推送按
`notifications.secret_push_minute` 触发，管理页不提供密函调度修改参数。签到记录清理目前没有持久化配置字段，修改只影响
当前进程，重启后恢复内置规则。

可永久删除的任务是每日签到、密函推送和公告轮询；签到记录清理任务只能暂停/恢复。永久删除
会把任务 ID 原子写入运行期 `scheduler_state.json` tombstone，任务从列表隐藏，后续重启也跳过，
API 和页面均不提供恢复。只有删除前备份存在时，部署者才能在停机后审核并恢复该 JSON 文件；
没有备份时按不可恢复处理。相关操作前的完整备份/回退步骤见
[维护文档](../dev/maintenance.md)。

## 离群用户探测与删除

成员探测只支持 `aiocqhttp`/OneBot V11 的 raw client `get_group_member_list`。页面先读取能力，
非该平台或能力不可用时提前禁用按钮；后端仍会拒绝 `unsupported` 请求，不会把能力缺失当作
`absent`。

探测结果严格分为 `present`、`absent`、`unknown`：接口缺失、网络/平台错误和响应不完整都是
`unknown`。单群清理只有明确 `absent` 才能执行，并且只清理该用户在该群可归属的个人密函订阅。
全局删除前后端都会重新扫描全部关联群；任一 `present`、`unknown` 或不支持都会阻止全局删除。

通过安全门禁后，全局删除会移除该用户的全部绑定、凭据、个人隐私、个人密函订阅，以及其所有
关联 UID 的签到历史（即使 UID 仍被其他用户绑定）。群强制隐私、群级订阅、群级签到结果和通知
资源不随用户删除；SQLite 与 JSON 没有同一物理事务，部分失败必须按逐项结果重试。

## 角色与武器别名

默认角色和武器别名来自资源仓库，只读、不可替换或删除；自定义别名分别写入
`alias_custom.json` 与 `weapon_alias_custom.json`。聊天管理员命令支持逐项添加/删除、保留
custom 的恢复，以及清空两类 custom 的强制恢复。已移除的 `panel_custom/` 仅保留历史文件，
不会被管理页或插件读取、统计、删除。

## 迁移、备份与回滚

`0003_global_identity` 是破坏性迁移：它删除并重建账号、凭据和两张隐私表，旧账号、凭据及隐私
行不保留，`sign_records` 保留。`0004_app_credentials_only` 进一步物理删除凭据表的五个
Web 列，只保留 App 字段。`0005_auto_sign_enabled` 只新增默认开启的自动签到开关字段。
执行前必须停止写入并备份 `dnaby.sqlite3`，同时按需要备份
`subscriptions.json`、`ann_state.json`、`scheduler_state.json`、`alias_custom.json` 和
`panel_custom/`；这些备份可能含明文凭据，必须限制访问且不得提交或外传。

迁移失败应停止部署并保留原错误。需要回退时，停止新版本，使用普通 revert/旧版本部署，并
同时恢复与旧代码匹配的迁移前数据库备份；`downgrade` 只能重新创建空 Web 列，不能恢复已丢弃
的凭据行。
绝不能只回退代码，或让旧版本直接读取新 schema。任务 tombstone、别名和面板删除也只能依靠
相应的操作前备份恢复，页面不提供撤销。

## 已知限制

隔离测试和浏览器验收使用临时数据、虚构账号/fake transport；没有真实游戏凭据、上游或 T2I
服务时，预览图片可用性不代表生产验收。`aiocqhttp` 以外的平台不能使用成员探测和基于成员状态的
全局删除安全门禁。
